Prise en main de l'environnement

10 min ▶

Attention : l'environnement est éphémère. Si vous fermez l'onglet, vous perdez votre travail. Restez sur la page jusqu'à la fin du TP (session de 60 minutes).

  1. Ouvrir votre navigateur et aller sur l'URL suivante : killercoda.com/playgrounds/scenario/ubuntu
  2. Se connecter (via Google, GitHub ou e-mail). Si vous utilisez votre adresse universitaire, vérifiez vos mails : un lien de connexion vous a été envoyé.

Une fois chargé, un terminal noir apparaît.

  1. Taper la commande suivante pour vérifier qui vous êtes : whoami. Notez que vous êtes root : c'est le « super-administrateur ». Sur cet outil, vous avez tous les droits par défaut.

15 min ▶

Puisque vous êtes root par défaut, vous avez tous les droits. Pour simuler une situation réelle et comprendre les permissions, nous allons créer un utilisateur standard.

  1. Création d'un utilisateur : créer un utilisateur nommé etudiant : adduser etudiant (remplir les infos demandées ou appuyer sur Entrée).

5

Création d'un alias

20 min ▶

Nous voulons que l'adresse .../test pointe vers un dossier qui n'est pas dans /var/www/html.

  1. Préparation (en tant qu'utilisateur etudiant) : créer un dossier ~/dossier_test dans votre répertoire personnel, puis un fichier index.html dedans avec le texte « Ceci est un Alias ». Noter le chemin absolu de ce dossier (pwd) : probablement /home/etudiant/dossier_test.
  2. Configuration Apache : revenir en root (exit), se déplacer dans /etc/apache2/conf-available/ et créer un fichier mon_alias.conf avec nano, contenant la configuration ci-dessous (adapter le chemin si besoin).
Alias /test /home/etudiant/dossier_test
<Directory /home/etudiant/dossier_test>
    Require all granted
</Directory>
  1. Activation : activer la configuration : a2enconf mon_alias
  2. Recharger Apache : systemctl reload apache2
  3. Tester l'URL de votre site en ajoutant /test à la fin.

Si vous avez une erreur Forbidden (403), c'est souvent car le dossier /home/etudiant n'est pas traversable. La commande chmod o+x /home/etudiant corrige cela.

Logs et diagnostic

10 min ▶

Un développeur doit savoir pourquoi son site plante.

  1. Observation en temps réel : s'assurer d'être root, puis lancer la surveillance du journal d'accès : tail -f /var/log/apache2/access.log

7

Sécuriser un dossier (authentification)

20 min ▶

Contexte : vous développez une interface d'administration (/admin). Elle ne doit pas être accessible à tout le monde. Nous allons mettre en place une « Basic Authentication » via un fichier .htaccess.

  1. Préparation : dans /var/www/html, créer un dossier nommé admin et, à l'intérieur, un fichier index.html contenant « ZONE SECRÈTE ».
  2. Configuration globale : par défaut, Apache ignore les fichiers .htaccess pour des raisons de performance. Éditer nano /etc/apache2/apache2.conf, chercher le bloc <Directory /var/www/>, changer AllowOverride None en AllowOverride All, sauvegarder et recharger Apache (systemctl reload apache2).
  3. Protection locale : dans le dossier /var/www/html/admin, créer un fichier nommé .htaccess avec la configuration ci-dessous.
AuthType Basic
AuthName "Zone Admin"
AuthUserFile /etc/apache2/.htpasswd
Require valid-user
  1. Création des identifiants : créer le fichier de mots de passe chiffrés avec l'utilitaire htpasswd : htpasswd -c /etc/apache2/.htpasswd monlogin (remplacer monlogin par votre prénom), puis définir un mot de passe.
  2. Test : accéder à .../admin via le navigateur. Une fenêtre de connexion doit apparaître : renseigner le nom d'utilisateur et le mot de passe créés précédemment.

Votre page secrète doit s'afficher !

8

Personnalisation des erreurs (UX)

15 min ▶

Contexte : la page « 404 Not Found » par défaut d'Apache est austère et technique. En MMI, on soigne l'expérience utilisateur.

  1. Création de la page : créer un fichier /var/www/html/oups.html avec un design sympa (un message « Perdu dans la Galaxie MMI ? » par exemple).
  2. Configuration : éditer le fichier de configuration du site par défaut /etc/apache2/sites-available/000-default.conf et, à l'intérieur du bloc <VirtualHost *:80>, ajouter la ligne ErrorDocument 404 /oups.html. Recharger Apache.
  3. Application : tester une URL inexistante (ex : .../toto.html). Votre page personnalisée doit s'afficher à la place de l'erreur standard.
